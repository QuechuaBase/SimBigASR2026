SIMBig 2026 Shared Task

Data and Baselines

Datasets, baseline systems and evaluation protocol for Task 1 (Puno Quechua ASR)

Code, baselines and evaluation scripts: github.com/QuechuaBase/asr-puno-quechua (Apache-2.0)
Trained models: huggingface.co/QuechuaBase

Training data

Task 1 uses the Mozilla Common Voice datasets for Puno Quechua (ISO 639-3 qxp), released to participants on 24 August 2026. Both are available on Mozilla Data Collective under CC0 1.0.

Scripted speech

Common Voice Scripted Speech: Puno Quechua

Read sentences recorded and validated by volunteer speakers on the Common Voice platform.

Current release 27.0 (11 Sep 2026): 34.9 h total · 31.2 h validated · 25,423 clips · 81 speakers
Mozilla Data Collective

Spontaneous speech

Common Voice Spontaneous Speech: Puno Quechua

Unscripted answers to open questions, transcribed by the community.

Current release 5.0 (11 Sep 2026): 35.4 h total · 5.2 h validated · 7,305 clips · 110 speakers
Mozilla Data Collective

Train and dev splits were chosen by each team from the Common Voice data and are described in their system description papers.

Test set

All systems were evaluated on the same held-out test set of Puno Quechua speech, released (audio only) on 30 September 2026: 659 clips · 59 minutes · 7 speakers.

TypeClipsDurationDescription
Scripted43825.7 minRead-aloud sentences
Spontaneous22133.5 minElder speakers answering open questions
Total65959 min7 speakers

Audio is 16 kHz, mono, 16-bit PCM WAV. The metadata file qxp_test_dataset.tsv gives each clip's file_name, speaker gender (female, male), age band (twenties, thirties, sixties = 60 or older) and type (scripted, spontaneous); these fields drive the leaderboard's breakdowns by gender and speech type.

Recording conditions: speakers recorded the clips themselves in a web browser on their own devices; rooms, microphones and background noise were not controlled.

Baselines

Baselines played two roles in the shared task.

1. Initial baselines (released at the start)

At the start of the task the organisers released a complete, reproducible pipeline and trained models, so that teams could begin from a working system: continued pre-training (CPT) of wav2vec 2.0 XLS-R on Puno Quechua audio, fine-tuning, and evaluation (pipeline.sh in the repository; models on Hugging Face). These results were reported in the repository on its own evaluation data, before the shared-task test set existed:

Evaluation

Word error rate (WER) and character error rate (CER) are the main metrics; teams are ranked by WER. The leaderboard also reports:

  • CER variants ignoring diacritics and ignoring spaces;
  • chrF: character n-gram F-score (higher is better);
  • Levenshtein distance per utterance;
  • word-level substitution, deletion and insertion rates;
  • WER broken down by speaker gender and by scripted vs spontaneous speech.

Text normalisation. Before scoring, both the reference and the system output are normalised:

  • Unicode NFC;
  • lowercase;
  • punctuation removed, except the apostrophe ', which marks ejective consonants (k'anka ≠ kanka); ñ is also kept.

Submission format. A tab-separated file named qxp.tsv, with no header and one line per test audio file. The test set includes a qxp.tsv template listing every file; teams replaced the placeholder text with their system's output.

qxp_008067c9b0cb.wav	your predicted transcription here

Scoring script: in the eval/ folder of the baseline repository.
